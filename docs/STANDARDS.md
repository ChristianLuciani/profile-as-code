# Repository standards & public-readiness policy

> Every row is a **record of a dated run**, not a live status poll: it cites its source, its date,
> and — for anything derived from the runtime (test counts, corpus size) — the command and the
> commit (`sha`) that produced the reading. A runtime figure is therefore *superseded* by a newer
> run's record, never silently "refreshed" in place, and no row asserts a number that moves with
> every commit as current state (#226). Where a figure has a derivable source it is generated, not
> typed: the documentation corpus census lives in the `<!-- gen:doc-links -->` block of
> `docs/ci-cd.md`, regenerated by `pnpm gen:doc-links` and asserted fresh by
> `node scripts/link-check/check.mjs --check` in CI; other runtime figures are quoted as
> `pnpm install --frozen-lockfile && pnpm build && pnpm test` at `<sha>` (`<date>`) → reading.
> Every status cites its evidence — a claim without source + date does not belong here (evidence
> rule). A run-citation a status row rests on carries its anchor inline,
> `<!-- evidence: <type> as_of=<sha> kind=record|current -->`, so its staleness is **computable**
> rather than a matter of opinion: `node scripts/evidence-gate/check.mjs` (CI) reports `fresh`,
> `stale` (a warning — re-measure, or mark it `kind=record` if it is history) or `unreachable`
> (the only failure: a sha rebased away leaves the claim without a source). A `kind=record`
> citation is correct forever and is never stale.

## Private by default

This repository **started** private under this policy and **flipped public** — measured 2026-10-24
(`gh repo view … --json visibility` → `PUBLIC`, row `Visibility`). The policy is unchanged for new
repositories: they **start and stay private** until they pass the Public-Readiness Checklists below,
with the maintainer's explicit sign-off. Policy ratified in the operator's global contract
(`repo-governance` §5, prompt-studio). The visibility flip and PR merges are **human-only** actions;
agents prepare, verify and leave everything ready, but never publish or merge on their own.

Rationale: a public repo is a commitment — anyone can fork, file issues and judge it. It must not
expose unfinished, unverified or untested work. This product must prove itself on **real user data**
before it is presented publicly — the first real end-to-end test is a hard requirement, not an option.

## Free-plan constraints (GitHub Free)

Branch protection and rulesets are **not available on private repositories** with GitHub Free
(the API returns 403 — they require GitHub Pro or a public repo). Verified empirically.

The era-while-private workarounds (this repo, until the flip — measured public 2026-10-24, #293):

- **Protection by access + process:** access was limited to the maintainer and their agents; every
  change went through a PR only the maintainer merges.
- **At the flip** the API protection returned — measured 2026-10-24: `main` carries classic branch
  protection (required checks `ci` + `sign-off`, strict; enforce-admins; conversation resolution) plus
  ruleset `main-basic` (registered 2026-08-18, enforcement **disabled**); `docs/ci-cd.md` keeps the
  API calls and the measured state.
- **Dependabot:** alerts and version updates for private repos are limited on Free (version updates
  effectively require public or Pro). While private, dependency bumps got the manual weekly review;
  the flip unblocks it (`.github/dependabot.yml` present, verified 2026-10-24).
- **Actions:** 2,000 minutes/month on private free repos — ample for this CI (~1 min/run); the flip
  makes usage **free** for standard GitHub-hosted runners (public repositories — GitHub Docs, fetched
  2026-10-24, [OFICIAL]).

## Applying this policy to new projects

When creating a new repository: `gh repo create <name> --private --source .` (or private in the
UI). Record both checklist statuses in the new repo's `docs/STANDARDS.md` copy (reference:
prompt-studio's own STANDARDS.md). Do not flip to public until all items are ✅ (or carry tracked,
non-blocking issues) and the maintainer signs off. **Re-evidence** this table before every flip
decision: each row must name a dated, reproducible run (`command` at `<sha>`) or read a generated
block (the `gen:doc-links` census). Editing a number in place is not re-evidencing it — a runtime
figure is superseded by a newer run's record, never silently updated. A table whose rows cannot
name their run is not a sign-off basis.
