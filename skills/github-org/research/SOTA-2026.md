# SOTA-2026 — GitHub org README / brand landing (brand flavor, M6)

Dated, evidence-tagged sources for the `github-org` skill. Claims without a
source + date do not enter (regla de evidencia).

## Sources

- **[OFICIAL] GitHub docs — "Creating a default community health file" / org
  profiles** (2026, github.com/orgs/community). Org READMEs render on the org
  landing page; they are the first page a visitor (human or LLM agent) sees.
- **[OFICIAL] schema.org — Organization type** (2026, schema.org/Organization):
  `sameAs`, `logo`, `foundingDate`, `slogan`, `description` are the machine-
  readable fields an LLM triangulates across surfaces.
- **[BENCHMARK] Handle-consistency pattern** (observado 2026-08-18 en el sweep
  de disponibilidad de handles de Topia Press, operador): la marca vive en 10+
  superficies (X, Bluesky, GitHub org, Substack, Instagram, TikTok, YouTube,
  Reddit, Mastodon, SoundCloud + dominio canónico); el drift manual de esa
  matrix es el problema que el engine resuelve (issue #25).
- **[EXPERTO] Brand voice vs personal voice** (2026, práctica de agencias de
  marca): una org no "habla como persona" — misión/tagline estables, un CTA
  primario, consistencia sobre autobombo. La voz de marca es la coherencia.

## Implicaciones para el renderer y la skill

1. El README del org es la **primera superficie GEO** de la marca: el JSON-LD
   `Organization` con `sameAs` = links + claimed handles es lo que un LLM cita.
2. La **handle matrix es el SSOT** de superficies (más fiable que adivinar de
   `identity.links`): filas `claimed` son surfaces vivas; `pending` no se
   despliegan.
3. **Consistencia = citabilidad** (SPEC §8): mismo nombre, misma misión, mismos
   handles en todas las superficies.
4. **Impersonación:** homónimos vivos no relacionados (p. ej. `topia.com`) →
   firmar siempre con el nombre completo de la marca.
